# Shared implementation contract

`src/main.js` owns composition and input; `src/game.js` owns simulation; `src/scene.js` owns rendering; `src/ui.js` and `src/style.css` own interface; `src/audio.js` owns sound. Define file ownership for each parallel task and preserve other workers' edits.

## Renderer

As of 0.2.1, each hazard is ONE resident in an open window with TWO complete mirrored arms. `scene.hands` holds window actors with `{group,person,head,torso,arms:[left,right],catchCenter,...}`. Both arms descend from the same `person` group and expose shoulder/upper/lower/elbow/wrist/cuff/palm/fingers/thumb. During an active grab, the average WORLD position of the two palms is exactly `(hazard.x,hazard.y,3)`; no imaginary central palm exists. Hunter target is shared by the pair. Retraction begins continuously after passed and returns the palms toward their owner. The same existing forgiving collision widths remain in game.js. Detailed invariant: `docs/ITERATION_03.md`.

Hazard IDs and pickup IDs are opaque strings, never numeric animation inputs. Hazards expose a finite numeric `phase`; pickups expose a finite numeric `at`. All transforms, opacity and color values sent to WebGL must be finite. `test:render` covers active hands/pickups and is included in `test:browser`.
`export class RainScene` with `constructor(container)`, `resize()`, `update(state, dt)`, `dispose()`. Import Three.js by `import * as THREE from 'three'`. Append WebGL canvas to container. Camera front view of a tall facade, with subtle perspective. All gameplay lives in x/y plane at z=3; character at `(state.x, 1.2, 3)`, playable x range [-6.65,6.65], facade edges at ±7.1. Facade z=0, five windows columns x=[-6,-3,0,3,6]. World moves upward as player descends. Hazards contain current `y` (same coordinates as player), `x` (tip/collision position), `baseX` (window), `type` ('grab'|'sweep'|'long'), `warning` (0..1), `active` boolean, `passed` boolean, `id`. Hands extend from window at z=0 toward z=3 and toward x when active. Show telegraph cyan/yellow to orange/pink BEFORE active. Pickups `{id,x,y,collected}` are little glowing raindrop crystals. Do not invent collision/render offsets. Static window grid spacing=10, offset=state.distance%10; rows align with hazard windows at y=1.2+distance-hazard.at. Ground at y=1.2+distance-state.height, appears only near landing. Render facade tall enough to cover camera. Hazards/pickups offscreen can be omitted/recycled. Menu: compose scene on RIGHT 60% with building/character prominent; gameplay centered. `state.mode` includes menu/playing/paused/caught/impact/result. `state.time` absolute animation time, `state.elapsed` simulation time; `state.level`, `state.distance`, `state.height`, `state.floors`, `state.speed`, `state.velocity`, `state.dashTimer` (seconds), `state.dashCooldown`, `state.slow`, `state.focus`, `state.shake`, `state.reducedMotion`, `state.outcome` ('win'|'caught'|null). Rain, city depth, window frames, rooftop details, player yellow raincoat dark hair boots, scarf secondary motion, volumetric-feel lighting, shadows, neon signage. Strong readable silhouettes. Stylized non-graphic landing bloom and rings. No external art required.

## UI
`export class GameUI` with `constructor(root, actions)`, `update(state)`, `toast(text, kind='info')`. The root is `#ui`; scene is `#scene`. Callbacks: `start()`, `retry()`, `next()`, `menu()`, `pause()`, `resume()`, `mute()`, `motion()`, `dash()`, `slow(held:boolean)`, `move(axis:number)` (touch left/right; pointer drag handled by main separately). UI must not own game simulation. View states: menu hero, playing HUD, pause panel, result screen (win/caught). `impact`/`caught` cinematic shows HUD only until main switches result. State fields above plus `score`, `combo`, `bestCombo`, `nearMisses`, `drops`, `bestScore`, `unlockedLevel`, `muted`, `progress` (0..1), `wind` numeric, `lastResult` `{score,nearMisses,drops,level,elapsed,bestCombo,newBest}`, `statusText` optional. No per-frame whole DOM replacement; create persistent structure and set properties. Menu Ukrainian, premium graphic editorial look, tiny English supporting labels. Brand RAIN / PAIN, acid-yellow, off-white, violet, ink-black. Full-screen canvas background, large left editorial hero, top masthead, bottom strip, confident typography with @fontsource fonts imported in main. Play starts via real button, instructions obvious, controls A/D or ←/→, Space dash, Shift slow, Escape pause, pointer drag/touch support. Original win phrase EXACT: "На вулиці rain — на душі pain" (user hyphen variant can use em dash in display). Retry caught copy playful surreal, no gore. Sound toggle (aria-pressed), motion toggle, local record shown. Touch actions show on touch/small screens and don't obscure center player. Accessible buttons focus visible. `data-action` identifiers useful for smoke tests. UI styles owned by worker; responsive 390x844 and desktop1440x900.

## Audio
`export class RainAudio` with `constructor()`, async `unlock()`, `setMuted(bool)`, `update(state,dt)`, `play(name)`, `dispose()`. Names: start/dash/near/drop/catch/impact/win/pause. Web Audio synthesized rain + original sparse ambient music, no external assets. Must unlock from first user gesture. No autoplay errors or excessive per-frame oscillator allocations. Optional mute persisted by root.

## Iteration 05 (0.4.0) — rooftop intro

Each run now starts in `mode='intro'` for 3.2 seconds, with finite introTime/introProgress and stages roof/approach/jump/transition. Gameplay clocks, fall distance, score and controls stay frozen. UI adds skipIntro(); Space/Enter skip, Escape/blur pause. Paused state preserves resumeMode to restore intro, including exact scene/camera frame. RainGame.start's third option `{skipIntro:true}` is only for gameplay fixtures; normal start shows the scene. The original 0.8s launch hop must not repeat in playing.

Scene intros use deterministic state time, actual grounded soles and a close rooftop camera. At completion/skip the flight coordinate is exactly (0,1.2,3), launchProgress=1 and normal camera returns. scene.introPose and read-only window.__RAIN_PAIN__.intro() expose active/stage/time, actual player/camera/feet coordinates for proof. Ragdoll, blood, window threats and flight HUD are inactive/hidden in intro. `takeoff` audio occurs once at jump or early skip. Full specification: docs/ITERATION_05.md.

## Iteration 04 (0.3.0) — landing style

`impactMode` is a saved menu setting ('arcade' default | 'hard'). `runImpactMode` snapshots it at start and is copied into lastResult; UI actions add `impactMode(mode)`. The previous non-graphic landing rules above apply to arcade. Hard+win has a 3.6-second physics/blood cinematic instead of arcade's 1.3 seconds; both end with the exact same phrase/grades/actions. Caught never activates landing physics/blood.

`RagdollPhysics` in src/ragdoll.js owns 13 Cannon bodies, 12 joints, the static street, fixed 1/120 step, contact and settlement, reset/dispose. RainScene exposes `ragdoll` and pooled `hardLanding` (`group`, visual `parts`, `particles`, `stains`, active/age). Only hard+win in impact/result runs it. Existing arcade updatePlayer/updateLanding presentation remains. Cleanup restores standard camera/player and hides stains. Root read-only probe adds landing() for browser verification. Full details: docs/ITERATION_04.md; archived old build: releases/arcade-0.2.1.

## Iteration 02 (0.2.0)

The current state extensions are specified in `docs/ITERATION_02.md`. Renderer additionally supports `hunter` hazards with numeric `targetX`, `phase`, `locked` and `stage` (tracking/locked/reaching/passed). The target locks at y=-7.2, then remains fixed through the grab; x/y always match collision. Risk pickups carry `risk=true` and use coral diamond styling. `launchProgress`, `fallSpeed`, `fallIntensity`, `nearTimer` and `pickupTimer` control flight presentation. All values remain finite, and settled flight preserves the character coordinate contract.

UI `actions.start(level?: number)` supports replaying unlocked towers; selection belongs to UI and is checked by main. `tutorialHint`, `riskDrops`, `lastResult.grade`, `lastResult.newLevelBest`, `lastResult.levelBestScore` and `levelRecords[level] = {score,grade}` support teaching, grades and per-tower records. Saves keep the existing rain-pain:v1 key and accept legacy data. Audio adds tracking/lock/risk events.
